Bcrypt 72-Byte Truncation Edge Case

Analysis of the 72-byte ceiling in Blowfish-based bcrypt implementations and OWASP mitigation.

Collision Mechanism:

Two distinct passwords sharing the first 72 bytes: 

P1: "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA_Secret1" (80 bytes)
P2: "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA_Secret2" (80 bytes)

Under legacy OpenBSD bcrypt truncation, bytes after index 72 are discarded. Consequently, bcrypt_hash(P1) == bcrypt_hash(P2), yielding an unintended password collision.

Modern Library Protection

Modern bcrypt (v4.0+) raises an explicit ValueError: password cannot be longer than 72 bytes to alert developers.

OWASP Recommendation

Pre-hash with SHA-256 before bcrypt (bcrypt(SHA256(password))), or migrate to Argon2id (supports passwords up to $2^{32}-1$ bytes).
